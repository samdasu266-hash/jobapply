# jobapply

지원 전형 일정 트래커. `index.html` 한 파일로 동작하며 빌드 과정이 없다.
데이터는 브라우저 `localStorage`에 저장되고, 설정하면 비공개 Gist로 기기 간
동기화된다.

## 기기 간 동기화

GitHub Pages에는 서버가 없다. `localStorage`는 브라우저마다 따로 놀아서 PC에서
찍은 탈락이 폰에 보이지 않는다. 그래서 두 기기가 같이 바라볼 저장소로 **비공개
Gist 하나**를 쓴다. 관리 드로어 → 기기 간 동기화 → 설정에서 `gist` 권한만 켠
classic 토큰과 Gist ID를 넣는다. 토큰은 그 기기의 `localStorage`에만 남고
`api.github.com` 외로는 나가지 않는다.

**밀어 넣기 전에 늘 먼저 읽는다.** 읽지 않고 쓰면 다른 기기에서 해 둔 일이
조용히 지워진다. 병합은 마지막으로 주고받은 스냅샷(`jobtracker.base.v1`)을
기준으로 삼는 3-way 방식이라, 한쪽만 건드린 항목은 그쪽을 따른다 — 폰에서
메모를 달았다고 PC에서 찍은 탈락이 날아가지 않는다. 양쪽이 같은 항목을 다르게
고쳤을 때만 그 기기가 이기고, 고친 쪽과 지운 쪽이 부딪히면 고친 쪽을 살린다.

동기화는 탭으로 돌아올 때·창이 포커스를 얻을 때·1분마다, 그리고 편집 직후에
돈다. 시트를 열어 둔 동안에는 화면을 갈아엎지 않으려고 건너뛴다.

`window.claude`가 있는 환경(Claude 아티팩트)에서는 기존 원격 DB 경로를 쓰고,
Gist 동기화가 켜져 있으면 그쪽이 저장 경로가 된다.

회귀 검사는 `api.github.com`을 가로챈 가짜 Gist와 브라우저 두 개로 이 경로를
실제로 태운다 — 연결·전파·동시 편집·삭제·토큰 거부까지 본다.

## 회귀 검사

```
node test/check.mjs          # 실패가 있으면 종료 코드 1
node test/check.mjs --keep   # 스크린샷을 test/out 에 남김
```

Playwright가 필요하다. 검사는 실제 브라우저에서 화면을 띄우고 확인한다.

**표시 여부는 반드시 계산된 스타일과 크기로 판정한다.** `el.hidden` 같은
속성만 보면 CSS가 덮어썼을 때를 놓친다 — 실제로 `.rmenu { display:flex }`가
`[hidden]`의 `display:none`을 이겨 메뉴가 항상 보이던 버그를 그렇게 놓쳤다.
`check.mjs`의 `shown()` 헬퍼가 이 판정을 담당한다.

검사 픽스처는 기본적으로 시드(미리 등록된 공고)를 넣지 않는다. 픽스처에
정의하지 않은 기관이 섞이면 결과를 읽을 수 없기 때문이다. 시드 자체를
확인할 때만 상태를 주지 않고 기본값으로 띄운다.

**`index.html`의 `SEEDS`에 공고를 추가하면 `check.mjs`의 `SEED_KEYS`에도
그 키를 넣어야 한다.** 빠뜨리면 `boot()`의 가드가 어떤 기관이 섞였고 무엇을
고쳐야 하는지 바로 알려준다. 가드가 없던 때는 엉뚱한 항목 다섯 개가
실패하는 것으로만 드러나 원인을 찾는 데 한참 걸렸다.

## 관리 화면의 구조

관리 드로어는 **목록만** 둔다. 고치는 일은 전부 시트에서 한다.

```
드로어    기관 목록 + 그 아래 일정 목록 + [+ 일정 추가] [전형 단계 일괄 추가]
일정 줄   → #evSheet    내용·날짜 + 접힌 장소/메모/차수 + 삭제·저장
기관 ···  → #instSheet  이름·상태·기본 장소·채용 링크·색상 + 삭제·저장
```

목록과 편집 폼을 한 화면에 세로로 쌓아두면, 목록에서 고른 항목의 폼이
한참 아래에 있어 둘 다 안 읽힌다. 컨트롤 140개·4.6화면이던 것이
45개·2.0화면이 됐다.

**`[hidden]` 은 전역 규칙으로 못박아 두었다.** `display` 를 지정하는
규칙(`.field`, `.sheet`, `.rmenu`)이 `[hidden]` 의 `display:none` 을
이겨서 "속성은 `hidden` 인데 화면에는 보이는" 버그를 세 번 냈다.
`check.mjs` 의 `shown()` 이 계산된 스타일로 보는 이유가 이것이다.
